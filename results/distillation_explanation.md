# Comparative Analysis: Sequence-Level vs. Logit-Based Knowledge Distillation

## 1. What Sequence-Level Distillation Trains On
Sequence-level knowledge distillation (Kim and Rush, 2016) trains the student model directly on the **complete target text sequences (hard targets)** generated by the teacher model. 

In this project, the teacher (Phi-3.5) generates raw text completions containing structured JSON strings given a natural-language command. The student model (Pythia-70M) is trained using standard autoregressive causal language modeling loss:
$$\mathcal{L}_{\text{seq}} = - \sum_{t=1}^{T} \log P_S(y_t \mid y_{<t}, x)$$
where $x$ represents the prompt command, $y = (y_1, \dots, y_T)$ is the teacher's decoded sequence of tokens, and $P_S$ is the probability distribution parameterized by the student. The loss is computed via cross-entropy against the one-hot target sequence generated by the teacher, treating the teacher as an automated data annotator or synthetic label generator.

---

## 2. What Logit-Based Distillation Trains On
Logit-based distillation (Hinton et al., 2015) trains the student model on the **continuous probability distributions (soft targets)** produced by the teacher's pre-softmax output logits across the entire vocabulary at each generation step.

Rather than predicting a single hard token, the student is optimized to match the full teacher distribution smoothed by a temperature parameter $\tau$:
$$q_i = \frac{\exp(z_i / \tau)}{\sum_j \exp(z_j / \tau)}$$
The objective minimizes the Kullback-Leibler (KL) divergence between teacher probabilities $q$ and student probabilities $p$:
$$\mathcal{L}_{\text{logit}} = \tau^2 \, D_{\text{KL}}(q \parallel p) = \tau^2 \sum_{k} q_k \log \left(\frac{q_k}{p_k}\right)$$
This objective transfers rich **dark knowledge**—the relative rankings, semantic similarities, and uncertainty over incorrect tokens—which provides vastly more gradient information per training token than a single hard label.

---

## 3. Why Logit-Based Distillation Is Not Possible in This Project
Logit-based distillation cannot be implemented in this workflow due to two fundamental architectural and infrastructural constraints:
1. **Black-Box Inference Interface:** The teacher model is served via Ollama's HTTP completion endpoint (`/api/generate`), which exposes only generated text strings. It does not provide access to the internal forward-pass logits, probability distributions across the vocabulary, or intermediate hidden activations.
2. **Vocabulary and Tokenizer Incompatibility:** Phi-3.5 and Pythia-70M belong to entirely different model families with disjoint tokenizers and vocabulary sizes (Phi-3.5 uses a 32,064-token SentencePiece/Llama-compatible tokenizer, whereas Pythia-70M uses a 50,304-token GPT-NeoX BPE tokenizer). Direct logit-matching requires an identical token vocabulary or an aligned projection matrix; logit matching across heterogeneous token vocabularies cannot be performed with standard token-level KL divergence.

---

## 4. Real Limitations of the Current Approach
A significant limitation of sequence-level distillation on this task is **error propagation and absence of uncertainty calibration**:
- Because the student is trained with standard cross-entropy on hard targets, it treats every teacher output as ground truth. Any hallucinations, subtle slot misalignments, or malformed JSON artifacts produced by the teacher are penalized equally with correct outputs and absorbed directly into the student's weights.
- Unlike logit distillation, the student receives zero signal regarding the teacher's confidence or alternative valid slot extractions (e.g., whether "seven thirty am" was chosen with 99% probability or a marginal 35% probability over "seven thirty").
- Given Pythia-70M's restricted parameter budget (70 million parameters), the model lacks sufficient capacity to recover from noisy training targets, resulting in syntax errors and slot hallucinations on unseen commands.
